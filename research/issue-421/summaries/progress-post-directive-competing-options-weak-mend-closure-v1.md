## Zero-row failure diagnosis

A deterministic read-only diagnostic used only the frozen content and the two
completed null outputs. Removing `emberHeart.weakMend = 0` left semantically
equal content, but the canonical content constructor had sorted 737 dictionary
paths. In particular, it changed the insertion order of the six affix keys.
Current `CombatRules.start_combat` samples `content.affixes.keys()`, so that
order is path-sensitive. Reward and event catalogue order changed as well.

The failure class is `candidate-content-construction-order-alias`: explicit
zero did not encode the frozen path even though the focused primitive was
isolated. This diagnosis explains the failure; it does not waive the frozen
futility rule or authorise a constructor repair.
